# Роли и вход в систему

Подробности запуска и устройства проекта — в [README.md](README.md). Здесь только роли, учётные записи и сценарии.

## Как открыть систему

1. В папке проекта запустите сервер:
   ```
   .venv/bin/python manage.py runserver
   ```
2. Откройте http://localhost:8000. Неавторизованного пользователя перенаправит на страницу входа.
3. Если демо-пользователей нет, создайте их (команда безопасна для повторного запуска):
   ```
   .venv/bin/python manage.py seed_demo
   ```

Пароль у всех демо-пользователей один: `Demo-pass-2026`.

## Что может каждая роль

| Возможность | Жилец | Диспетчер | Мастер | Начальник |
| --- | --- | --- | --- | --- |
| Видит заявки | только свои | все | только назначенные | своего участка |
| Подаёт заявку | да, с фото | да, по звонку от имени жильца | нет | нет |
| Принимает или отклоняет заявку | нет | да | нет | да |
| Назначает мастера, меняет приоритет | нет | да | нет | да |
| Берёт в работу, отмечает выполненной | нет | нет | да, свои | нет |
| Прикладывает фото | «до» | «до» | «после» | нет |
| Подтверждает выполнение и оценивает | да | нет | нет | нет |
| Отменяет заявку | да, пока она «Подана» | да | нет | да |
| Отчёты и выгрузка в Excel | нет | нет | нет | да |
| Справочники (дома, категории, сотрудники) | нет | нет | нет | нет, только администратор через `/admin/` |

Права проверяются на сервере. Чужая заявка по прямой ссылке открывается как «404», подделанный запрос получает «403».

## Статусы заявки

Подана → Принята → В работе → Выполнена → Закрыта.

Из «Подана» и «Принята» заявку можно отклонить, из «Подана» — отменить. Если жилец не принял работу, заявка возвращается из «Выполнена» в «В работе». Из финальных статусов («Закрыта», «Отклонена», «Отменена») заявка не выходит.

## Пошаговый сценарий «от заявки до закрытия»

1. **Жилец** (`resident@uk.local`): «Новая заявка» → категория, описание от 10 символов, при желании фото → «Отправить». Заявка получает номер вида `2026-000001`.
2. **Диспетчер** (`dispatcher@uk.local`): в очереди открыть заявку → выбрать мастера и приоритет → «Принять заявку». Считается срок по категории (для сантехники 48 ч, для аварийной 4 ч).
3. **Мастер** (`master1@uk.local`): в «Моих задачах» открыть заявку → «Взять в работу» → «Отметить выполненной» с обязательным фото «после».
4. **Жилец**: открыть заявку → поставить оценку 1–5 → «Подтвердить выполнение». Заявка закрыта.
5. **Начальник** (`chief@uk.local`): раздел «Отчёты» → выбрать отчёт → при необходимости «Выгрузить в Excel».

Письма жильцу и мастеру в прототипе печатаются в консоль, где запущен сервер.

## Заявка по телефону (диспетчер)

«Заявка по звонку» → найти жильца по ФИО, телефону или адресу. Если жильца нет, нажмите «Создать карточку нового жильца»: карточка создаётся без личного кабинета. Позже жилец может зарегистрироваться с тем же телефоном, и карточка свяжется с его аккаунтом.

## Регистрация нового жильца

1. На странице входа нажмите «Регистрация».
2. Заполните ФИО, телефон, e-mail, дом, квартиру и пароль, поставьте согласие на обработку персональных данных.
3. Откройте ссылку подтверждения из письма. В прототипе письмо печатается в консоль сервера.
4. Войдите с этим e-mail и паролем.

Без согласия на обработку данных регистрация невозможна. До подтверждения e-mail войти нельзя.

## Правила входа

- После 5 неверных попыток подряд вход для этого e-mail блокируется на 15 минут.
- Заблокированный сотрудник (поле «Активен» в админке) входить не может, а его история заявок сохраняется.
- Забытый пароль: ссылка «Восстановить пароль» на странице входа. Письмо также печатается в консоль.

## Как добавить сотрудника

Через админ-панель `/admin/` (нужен администратор):

1. Создайте пользователя: e-mail одновременно логин, пароль не короче 8 символов.
2. В разделе «Сотрудники» создайте запись: пользователь, ФИО, телефон, роль, участок.

Группа роли у пользователя назначится автоматически по выбранной роли.
